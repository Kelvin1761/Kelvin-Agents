## 0. 硬規矩（同 L1–L4 一樣，唔變）

- **只出解釋同假設，唔准直接調權重。** 「呢個部件排錯咗 N 對」唔可以拎嚟揀 leaf 或者調權重：
  EXP-20261013-01 證實過，將失手共識搬去下一段 dev 會蝕。每個部件一定要同時報**排錯 N 對／排啱 M 對**，淨計錯例會懲罰
  成日幫模型排啱嘅部件。
- 賽後資訊（SP、收盤價、競賽報告、走位、犯規、退賽、逐球）**只入解釋，永遠唔入組別或者特徵**。
  組別白名單要喺提案入口同 judge 兩邊共用，條件係 `available_at ≤ decision_at`。
- 新假設照舊行 L3：最多 2 個合法條件、每季去重＋Holm、3pp 門檻、只用出世後新數據、預定功效、≥30 日判一次 → L4 forward。

## 1. AU／HKJC：逐對拆解

**先重現當時公布嘅排名**，再拆。AU 原始分最高嗰匹可以被 `thin_evidence_swap` 調落第二。如果佢最後贏，第一句就要講
係邊條規則換走佢。

| 個案 | 規則 |
|---|---|
| a 大熱贏、模型排第二 | 全部場次。大熱 = 全場最低有效獨贏 SP（並列逐匹標記）。贏馬對公布首選：兩匹原始分、公布名次、換位原因。報價唔齊 = 熱門身份未確定。 |
| b 大場頭兩揀都上名 | 實際起步 **≥ 9 匹**，公布 #1、#2 都入前三。追**餘下嗰匹上名馬**（可能係頭馬）。佢排 #3／#4 就記命中；排 #5 或之後，就逐匹對模型 #3、#4，解釋兩道差距。 |
| c 冷門上名 | 獨贏 SP **≥ 10.0**（待 Kelvin 確認）。全部場次，入咗模型前四照記命中；漏出前四，就對前四入面實際名次最差嗰匹，睇係邊匹守住咗前四門檻。 |

按（賽日、場、兩匹馬）去重，保留 a／b／c 標籤；退出馬、死熱、缺快照、外置碟離線一律列「應有／缺」。

**拆分**：用同一份賽前快照（`Race_X_Auto_Scoring.csv`＋Logic `python_auto`）。逐對計「排前減排後」：leaf 差 → 維度 → 調整 → 正式分。
AU 用 `matrix_scores`、overlay、`final_rank_score`、`decision_trace`；HKJC 用 `matrix_*`、初出馬權重、全場修正、
`official_ranking_score`，同分再核 `ability_score_raw`、馬號（`matrixdisp_*` 只供顯示）。截斷、交互、四捨五入分開列，
對唔平就報未解釋差額。兩匹馬並排列 `score_provenance`／`feature_evidence_state`：60 分可以係實測中性，亦可以係冇數據。

**差幾多先追到**：固定其他輸入，淨改落後馬一個 leaf，喺合法值域重跑完整排名，記首次反超要郁幾多、反超後入唔入到前四、
有冇賽前原文支持嗰個值。超出值域 = 「單項追唔到」。呢個係量**敏感度**；只有獨立嘅賽前證據先可以叫「當時有線索」。

**分母**：每場每對有正式先後嘅馬都計一次（另外列 #1／#2 同前四邊界）。每個部件報「支持模型次序而排錯 N／排啱 M」，
加反向、中性、未知；移除差距後次序真係反轉先標「足以翻位」。跨日報場數、日數、按日 bootstrap CI。

## 2. 每個候選必交配對重播（Kelvin 嘅做法）

開發前先封存：保護賽日（非 holdout）、全場清單、快照 SHA、baseline 版本、成功定義。逐場用同一份輸入跑兩個版本，
就「首選贏」同「三匹上名馬全入前四」報**錯→啱、啱→錯、兩版啱、兩版錯**，附轉咗嘅場號。
要聲稱「保護日結果完全不變」，就要預先指定係邊個輸出逐場一樣（例如有序前四）；淨係「零啱→錯」唔夠證明。
**反覆望住保護日改參數 = 已經用咗保護日嚟開發**，要換一批新嘅。照舊另報全 dev 嘅 `paired.gap_change`＋CI、排名尺／市場尺同 forward。

## 3. NBA：逐腿解釋＋漏選

- **逐球（PBP）值得做，用 Python**：ESPN `site.api.espn.com/apis/site/v2/sports/basketball/nba/summary?event={id}`，本機快取每場
  ~450–510 個事件、~0.4MB；重用 `nba_espn_lineups.fetch_summary`（有快取就零請求）。逐條腿：盤線、實績、實際分鐘對預期分鐘；
  由 `period/clock/type/participants/比分` 還原：犯規麻煩坐咗幾耐、末節大比數坐板凳、在場回合、每分鐘出手、命中率、罰球。
  分鐘／出手／犯規要同 box score 對帳，對唔上就降級做「未知」。教練動機永遠係未知。
- **漏選**：用同一時刻嘅雙邊報價同 `nba_engine.featured.candidates` 建**全部候選池**，對 `featured_records`（sidecar 嘅 `picked` 係 SGM，唔係精選）。
  按盤種、方向、價帶分「入選／合資格未選／被規則剔除」，報 W/L、void、命中率、決策價紙上回報、同批去水基準，同場多腿按場聚類。
  **淨列「未揀但中」嘅腿幾乎一定會搵到假訊號**，所以冇全池分母就唔出。

## 4. 網球：逐注解釋

`prop_tracker.id` 對 `featured_picks.prop_id`，用同 NBA 一樣嘅全池分母，按每輪 card 凍結去重；模型評估用 `model_prob_raw`，回報用凍結價。
Ace 盤拆成發球局數 × 每發 Ace 率；總局／讓局睇盤數、保發破發、搶七；一發二發、接發得分率對賽前同場地基準（附樣本量）。
退賽／棄權依 `settle/props.py`，void 另列。逐分來源未核實：冇就停喺場級統計，並列每個巡迴級別嘅覆蓋率。
