# Wong Choi Stage 5 D-AU producer engineering checkpoint — 2026-09-13

## Decision

The metadata-only D-AU building blocks are locally implemented and tested, but
they are **not connected to the AU production scheduler**. No prediction,
settlement, scoring, Dashboard, Telegram, model, ruler or production state was
changed. Scheduler integration needs an explicit production-adapter approval.

## Scope implemented

- `immutable_snapshot.create_immutable_snapshot` can admit generated byte
  artifacts directly into a create-only snapshot. Safe basenames, non-empty
  bytes and source-name collision checks are mandatory; generated files never
  appear in or mutate the source meeting folder.
- `au_research_evidence.build_feature_projection` reads one completed AU
  meeting and builds a deterministic, promotion-denying projection. Each scored
  race must have exactly one Racecard, Formguide and Facts input; every feature
  binds those source filenames, byte digests, cutoff time, horse, feature and
  derivation identity.
- The same projection hash-pins `odds_history.json` and selects only the earliest
  `analysis` snapshot at or before cutoff. A morning refresh is never substituted
  for a missing analysis price.
- `settlement_artifacts` resolves the canonical full result
  `Race_Results_Reflector.md` together with the meeting reflector report and
  fails closed if either is absent.
- The shared AU read-only consumer accepts the new hash-bound projection while
  keeping legacy snapshots readable. It rechecks the projection digest,
  event/cutoff, exact Logic-file digests, exact horse set and every source
  artifact before reporting feature availability.

## TDD and evidence

The RED phase first failed because the additional-file API and AU producer did
not exist. A second RED phase reproduced the missing production integration:
the current scheduler neither supplies generated projection bytes nor pins the
canonical full result. Direct scheduler editing was then stopped by the
production-adapter safety boundary and was not bypassed.

After implementing only the non-production building blocks, the 46-test
cross-component slice passed. The full AU daily suite passed 345 tests and the
full shared Wong Choi suite passed 1,202 tests. They cover
create-only/idempotent snapshot admission, unsafe name and collision rejection,
source non-mutation, missing input failure, Sydney-time cutoff handling,
earliest-analysis odds, no morning-price substitution, canonical settlement
pair resolution, legacy compatibility and forged projection rejection.

The repository full gate then passed every configured suite: AU, HKJC, NBA,
Tennis, shared racing, shared Wong Choi, race compliance, agent scripts and
Dashboard Python/Node. AU and HKJC scoring goldens and generated model
documentation were unchanged. The isolated worktree contained no scored race
corpus, so its AU/HKJC data-contract checks were skipped rather than failed.

A read-only run against `2026-09-13 Dalby Race 1-8` produced an in-memory
projection for 8 races, 69 horses and 1,311 feature entries, with earliest
analysis odds present for all 8 races and `model_promotion_allowed=false`.
Nothing was written to the meeting folder or evidence store.

## Explicitly not done

- no import or call from `au_daily_schedule.py`;
- no new immutable production snapshot or settlement record;
- no historical backfill or reinterpretation of old snapshots;
- no AU engine, feature value, weight, odds policy or recommendation change;
- no commit, push, merge, activation, scheduler install or Dashboard deploy at
  this checkpoint.

## Required next approval

Approve D-AU production-adapter integration as a separate scope. The integration
must pass the generated projection to the existing immutable snapshot before
publication, add Racecard/Formguide/Facts/odds inputs to that snapshot, and pin
both canonical result and reflector report during future settlement. Missing
metadata must block evidence/publication rather than silently publish an
unverifiable Stage 5 sample. Full AU and repository gates plus rollback evidence
remain mandatory before release.
