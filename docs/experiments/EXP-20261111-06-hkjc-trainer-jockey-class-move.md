# EXP-20261111-06 HKJC 練馬師／騎師帶馬升班、降班嘅表現（screening）

- **日期**：2026-11-11（假設同判決規則喺睇結果之前寫）
- **平台**：HKJC
- **觸發**：Kelvin 睇完 EXP-20261111-05 後要求：「練馬師帶馬升班或者降班 test，also test the jockey」
- **假設（兩條，各自獨立判）**
  - **H1 練馬師**：練馬師喺「匹馬今仗相對上仗升班／同班／降班」呢個情境嘅上名超額（相對佢自己整體）
    係穩定特質，而且喺現有訊號＋匹馬本身升降班之上加到排序力
  - **H2 騎師**：同上，換成騎師
- **搜索過嘅舊記錄**：EXP-20261111-05（練馬師 × 班次，REJECT）；EXP-20260904-09 同 memory
  `hkjc-class-advantage-is-arbitraged-away`（**匹馬本身**跌級／升級 AUC 0.4819／0.4662，死）；
  `hkjc-class-history-carries-no-signal`。**冇人測過「人 × 升降班」**。AU 嘅 class move 記錄（EXP-20261009-02）係 AU 匹馬層面，唔同
- **改到嘅檔案／組件**：**冇。純量度**

## 方法（預先定，同 EXP-20261111-05 同一套）
- **語料**：`pit_backtest.load_all_rows()`
- **班次階梯**：C5=5、C4=4、C3=3、C2=2、C1=1、Group 1/2/3=0；Griffin／Unknown = 冇階梯
- **升降班**：用同一 `HorseID` 嘅上一仗（`Date < 今仗`）。今仗階梯數細過上仗 = 升班，大過 = 降班，相等 = 同班；
  冇上仗或者任何一邊冇階梯 = 「冇前仗」，唔計 delta（=0）
- **特徵**：`t_mv` = EB(練馬師, 升降班) 超額 − EB(練馬師) 超額；`j_mv` 騎師一樣。k=100，walk-forward `Date < 賽日`
- **baseline 特徵**：騎師整體、練馬師整體、練馬師同程、練馬師場地，**加匹馬升班／降班兩個 dummy**
  （咁先分得開「人」同「匹馬升降班本身」）
- **OOS**：2025-09-01 起；logistic；配對 bootstrap 400，按場次重抽
- **多重比較**：兩條假設，CI 用 97.5%（Bonferroni ÷2）

## 判決規則（各自，只開一次）
- **PASS（值得做引擎 A/B）**：加落 baseline 之上 Δ AUC 97.5% CI 下界 > 0，**而且**跨季 r
  （24/25 → 25/26，同一 (人, 升降班) ≥30 仗）CI 下界 > 0
- 唔過 → **REJECT（screening）**
- 唔換階梯定義、唔換 k、唔換 OOS 窗、唔改用「最近兩仗」去救

## 數據
- **語料**：23,253 行（2024-09-08 → 2026-11-08）；升降班：同班 18,374／降班 1,495／升班 1,103／冇前仗 2,281
- **OOS**：2025-09-01 起 12,935 行 / 1,040 場；94.3% 有升降班
- **覆蓋**（有前仗行）：練馬師×升降班 ≥30 仗 96.9%；騎師×升降班 ≥30 仗 93.9% —— 唔係樣本問題

## 結果

### 判決項（97.5% CI）
| 測試 | Δ AUC | |
|---|---|---|
| **H1 練馬師 × 升降班**，加落 baseline（含匹馬升降班） | **+0.0001 [−0.0001, +0.0003]** | ➖ |
| **H2 騎師 × 升降班**，同上 | **−0.0000 [−0.0001, +0.0001]** | ➖ |
| 騎師加落練馬師之上 | −0.0000 [−0.0001, +0.0001] | ➖ |
| 練馬師／騎師加落市場之上（對照） | +0.0000 | ➖ |

單獨 AUC（有前仗行）：`t_mv` 0.4892、`j_mv` 0.4703 —— 兩個都低過 0.5。

### 分升／降班（97.5%，bootstrap 200）
| | 練馬師 Δ | 騎師 Δ |
|---|---|---|
| 升班（604 行） | −0.0004 [−0.0020, +0.0013] | −0.0010 [−0.0150, +0.0130] |
| 降班（875 行） | +0.0009 [−0.0049, +0.0072] | +0.0024 [−0.0045, +0.0094] |
| 同班（10,714 行） | +0.0001 [−0.0001, +0.0002] | +0.0000 [−0.0000, +0.0001] |

### 穩定性（(人, 升降班) ≥30 仗）
| | 跨季 r | 拆半 r |
|---|---|---|
| 練馬師（33／41 格） | **−0.553 [−0.837, −0.043]**（反向） | +0.183 [−0.379, +0.615] |
| 騎師（31／44 格） | **+0.616 [+0.136, +0.870]** ✅ | +0.475 [+0.148, +0.852] ✅ |

騎師嗰邊**係穩定嘅**，但加唔到排序力。似係揀坐騎模式（邊個騎師多啲坐升班馬）而唔係騎功：
`j_mv` 同騎師整體 ρ −0.278、同升班 +0.173 —— 佢量嘅嘢已經喺騎師分同匹馬升降班入面。
練馬師跨季係**反向**：上季帶升班馬好嘅練馬師，今季反而差 —— 冇特質可言。

## 順帶發現（唔喺預先登記範圍，只做說明）
匹馬**本身**升降班單獨加落騎練之上係 ✅（+0.0063 [+0.0013, +0.0108]；升班超額 +8.13pp、降班 −2.89pp），
睇落同 memory「升降班已死」矛盾。核實：**升班馬 52.2% 上仗係贏咗**（同班 6.4%）—— 香港贏咗就升評分、升班。
加落「上仗名次＋上仗贏＋近 3 仗上名率」之上 Δ **−0.0001 [−0.0007, +0.0004]**。即係升降班＝form 嘅影子，
模型已經有 form，冇新資訊。舊結論（`hkjc-class-advantage-is-arbitraged-away`）企得住。

## 檢查
- **leakage-audit**：PASS —— 升降班只用同一匹馬 `Date < 今仗` 嘅上一仗；所有先驗 walk-forward；賠率只做對照
- **golden_scoring**：冇郁（冇改 code）；**data_contract**：不適用；**退步**：冇

## 結論
H1、H2 都 **REJECT**。練馬師帶馬升／降班冇延續性（跨季反向）；騎師嗰個有延續性但係揀坐騎習慣，
騎師分同匹馬 form 已經食晒。連同 EXP-20261111-05，**「人 × 班次」兩個切法都冇剩餘訊號**。
同 HKJC 讓磅制度一致：班次資訊被評分制度抹平，剩低嘅喺 form 同負磅已經捉到。

**決定**：REJECT（screening）—— 唔開引擎 A/B
**commit**：未 commit 任何 model code（冇改）
