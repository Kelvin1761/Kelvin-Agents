## 方法
`patches/hkjc_scenario_check/diag_scenario_magnitude_surface.py`：同 EXP-20261119-10 一樣量法（強偏差日 = 同日其他場次某類殘差 ≥ +10pp，
量該類馬自己殘差，強 − 平常日），唯一分別：**日偏差只用同日、同一種跑道嘅其他場次**，結果按今場跑道分開。dev 2020–23、holdout 2024–25，
按賽日 bootstrap 95% CI（500 次，seed 20261127）。

**預先登記判決（跑之前寫入腳本）**：全天候另用一套，要被利嗰類同時：強偏差日 n ≥ 150、全天候效應同草地差 ≥ 2pp、dev／holdout 同向。
唔符合 = 保留共用（跑法 ±2pp、檔位 ±3pp）。+5pp 門檻只作敏感度。

## 第一次跑：撞到數據 bug（照記）
第一次 holdout 全天候強偏差日 n = 0。原因：**賽果 index 2024、2025 兩季 `course` 欄全部 None（974 場）**，跑道只寫喺 `sectional_times`，
168 場全天候被當草地。live 賽果庫（`HKJC_Race_Results_Database`）一樣：2024 季 847 場、2025 季 852 場 `course` 全空，2026 季漏 7 場全天候。
腳本改為 `course` ＋ `sectional_times` 一齊睇之後重跑（下面係修正後結果）。

**副作用（另案）**：`hkjc_racing_engine/performance_figure.py:77` 用 `course` 判泥地 → 2024–25 全天候往績冇入「泥地分段」（`tags.py` 嘅泥地表現標籤，**未入分**）。
主表現數字係每場自己比較、直路 1000m 分段唔受影響（全天候冇 1000m）。未修，另開。

## 解讀
- 草地數字同 EXP-20261119-10 一致（守中 +2、內檔 +3），現行共用幅度其實係草地幅度，冇問題。
- 全天候樣本細（6 季 5,917 馬次，每日 2–3 場），CI 闊過 ±8pp；只有守中過預先登記規則，而且係**反方向**：
  「同日其他全天候場守中著數」嘅日子，慣性守中馬反而略差（−2.7，CI 跨零）。即係全天候「利守中」情境冇證據會幫到守中馬。
- 全天候放頭 +10pp（dev +13.2）係全表最大，同「全天候利放頭」嘅常識一致，但 holdout 量唔到，**未過驗證**，唔可以據此加大幅度。

## 建議（純顯示，唔郁正式排名／ROI）
按預先登記：只改全天候「利守中」—— 守中嗰格由 +2 改 0（量到嘅係負，情境唔應該反向郁）；其餘全部保留共用。
另一選擇：全部保留，只喺全天候場 banner 註明「全天候幅度未能分開量度」。

## Kelvin 決定（2026-11-27）
Kelvin：「手動揀嘅預設情境唔需要樣本啦，照做住先」，揀「全天候利放頭加大」（唔係上面預先登記建議嘅「利守中改 0」）：
- `hkjc_racing_engine/summary.py`：`SCENARIO_STYLE_PP_AWT = {"放頭": {"放頭": 6, "守中": 0, "後上": -6}}`、`SCENARIO_STYLE_FULL_PP_AWT = 6`，
  經 `scenario_constants()["awt"]` 出；量到 +10pp，取 ±6pp 保守值。其餘情境（包括利守中、檔位）全天候同草地一樣。
- Dashboard：全天候場（`battlefield.surface` 泥地）揀「利放頭」用全天候幅度，banner 寫明「樣本少、未過 holdout 驗證」。
- 正式排名、頭兩選、ROI 冇郁；情境只係手動 what-if。舊場次要重新評分先有 `scenario.awt`。
- 呢個係用戶決定，唔係預先登記判決嘅結果；證據等級 = 單一窗口 dev 訊號（+13.2pp，n 141）。
