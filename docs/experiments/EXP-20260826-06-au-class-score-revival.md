**狀態：REJECT（唔上線）**

## B) 照 HKJC `class_advantage` 形狀重砌維度（gain 按 lockstep 重 fit）

| 組成 | 乾淨 dev | 乾淨 holdout | 全語料 dev | 全語料 holdout |
|---|---:|---:|---:|---|
| rating .70 + class .30 | +0.0024 | +0.0016 | +0.0004 | **+0.0037 [+0.0008, +0.0066] ✅** |
| rating .70 + class .60 | +0.0026 | +0.0017 | +0.0003 | **+0.0048 [+0.0011, +0.0088] ✅** |
| rating .70 + class 1.00 | +0.0027 | −0.0007 | −0.0014 | +0.0055 [+0.0009, +0.0103] |

| rating .70 + class .60 + weight .30 | +0.0025 | +0.0022 | +0.0009 | **+0.0047 [+0.0008, +0.0087] ✅** |
| rating .70 + class 1.00 + weight .60 | +0.0030 | −0.0005 | −0.0009 | +0.0042 [−0.0007, +0.0091] |

**全語料有三個組成過閘。點解唔可以信：**

1. **全語料嘅 dev 幾乎變零**（+0.0003~+0.0009），而乾淨語料嘅 dev 係 +0.0023~+0.0030。
   多出嚟嘅 578 場（2026-06 之前）自己單獨測，**dev 每一個組成都係負**
   （−0.0003 ~ −0.0043）。即係話個「改善」唔係嗰批舊場次帶嚟嘅。
2. 嗰 578 場正正就係 [[au-archive-rescored-post-race]] 講嗰批 —— 賽後先重新評分，
   所以 `career_starts` / `latest_place` 呢啲 `class_score` 嘅輸入反映咗較後嘅狀態。
3. **最關鍵：gain 係喺 dev 度 fit 嘅。** 全語料嘅 dev 有三分一係污染資料，
   fit 出嚟嘅 gain（2.3768）同乾淨語料 fit 出嚟嘅（2.5893）**唔同** ——
   即係兩個語料測緊嘅根本係**兩個唔同嘅候選**。喺污染資料上 fit 一個尺，
   就係今朝先修好嗰個 `pace_perf` gain bug 嘅同一個病
   （[[au-display-gain-fitted-on-dead-corpus]]）。

## C) 幾個「單獨唔夠力」嘅 leaf 夾埋會唔會夠力？——唔會，佢哋互相重複

| 候選 | dev ΔAUC | holdout ΔAUC |
|---|---:|---|
| 只 class | +0.0026 | +0.0017 [−0.0029, +0.0064] |
| 只 sectional | +0.0017 | +0.0018 [−0.0029, +0.0064] |
| 只 distance | +0.0006 | −0.0015 [−0.0048, +0.0014] |
| class + sectional | **+0.0027** | +0.0027 [−0.0032, +0.0086] |
| class + distance | +0.0033 | +0.0014 [−0.0035, +0.0062] |
| 三個一齊 | +0.0022 | +0.0011 [−0.0046, +0.0068] |

class 單獨 +0.0026、sectional 單獨 +0.0017，夾埋得 **+0.0027**（唔係 +0.0043）。
**加法唔成立 = 佢哋捉緊同一件事。** 呢個同天花板實測（GBM 餵同一批 leaf 輸現行
線性組合 0.0099）完全一致：現有特徵之間已經冇剩低嘅正交資訊。

## 判決

**REJECT。** 乾淨語料上，`class_score` 嘅 holdout 區間由頭到尾跨 0。
全語料嗰三個「✅」係喺污染資料上 fit gain 嘅產物，唔算數。
