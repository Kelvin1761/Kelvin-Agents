# EXP-20261111-15 HKJC 換配備訊號：逐個配備分開量

- **日期**：2026-11-11
- **平台**：HKJC
- **假設**：某啲配備嘅變動（初戴／除去／重戴）會令馬匹表現好過「冇換配備」嘅同類馬。
- **搜索過嘅舊記錄**：EXP-20261010-05（除去配備 −3 剷走，所有配備夾埋量）、EXP-20260826-07（AU 配備變更，同 form 重複）。
  HKJC 之前冇逐個配備分開量過；`hkjc_expanded_corpus.py` 寫明賽果庫重建唔到配備。
- **改到嘅檔案／組件**：`docs/experiments/patches/hkjc_gear_events/gear_events.py`（新，純診斷）。冇郁引擎。

## 配置
- **baseline**：main `82322418`。配備喺 live 只做顯示，唔入分。
- **candidate**：冇。呢個係量度，唔係模型改動。

## 數據
- **語料**：排程 cache 嘅逐駒往績頁（`<場次>/.hkjc_cache/profile_cache.json` 46 份 + `wongchoi-scheduler/.hkjc_cache`），
  合併後 2,442 匹、36,831 仗。HKJC 喺配備欄自己標變動：`B1` 初戴、`B-` 除去、`B2` 重戴
  （實測：`1` 3,207 次全部之前冇戴過；`-` 3,503/3,554 上仗有戴；`2` 1,093/1,270 以前戴過但上仗冇戴）。
- **樣本**：33,987 仗非初出（2020-11 → 2026-11-08）；control = 冇任何變動標記 28,310 仗（入位 29.8%、勝 10.0%）。
- **三把尺**（全部對 control）：
  1. 對市場：今仗入位 − 同賠率段（25 段）control 入位率。
  2. 對自己：今仗輸距 − 「上仗輸距相同嘅 control」今仗輸距（處理均值回歸）。
  3. 原始入位／勝率（參考）。
- CI = 以馬匹做 cluster 嘅 bootstrap 4,000 次；逐格 p 做 Holm（每種變動 × 每個配備，n ≥ 40）。

## 檢查
- **leakage-audit**：PASS —— 變動標記喺排位表已印，賽前拎得到。賠率只做 benchmark，冇入任何特徵。
- **golden_scoring**：冇郁（冇改引擎）。
- **限制**：
  - 存活者偏差：cache 只有 2026 年出過賽嘅馬，佢哋舊年嘅仗係「留得低」嘅馬。對市場嗰把尺受影響較細，原始入位率受影響。
  - 終盤獨贏賠率係 benchmark，唔係賽前拎到嘅價。
  - 「對自己」只按上仗輸距配對，冇控制班次／路程變動。
  - 33 格一齊睇，Holm 之後對市場冇一格 < 0.05。

## 結論
原始數字睇落換配備之後大進步（初戴上仗入位 13% → 今仗 24%），但呢個係均值回歸：換配備嘅馬上仗跑得差，
同上仗輸距一樣而冇換配備嘅馬比，初戴反而差 0.3 馬位，市場亦已經完全計咗（−0.3pp）。
**冇任何一個配備嘅初戴有可靠嘅正面效果。** 兩段時間方向一致嘅只有：除去綁繫舌帶／除去頭罩（市場低估約 5–6pp）、
重戴（市場高估約 4pp）、鼻箍任何變動（差）。全部係對市場嘅 cohort 差距，Holm 後唔顯著，亦未驗證喺模型之上有冇剩餘訊號。

**決定**：MEASUREMENT（唔改模型；配備維持只做顯示）
