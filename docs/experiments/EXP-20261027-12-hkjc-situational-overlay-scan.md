## Pattern（凍結，10 個）

馬匹身份 = 馬名括號烙號。「上仗」= 呢匹馬最近一次有完成名次嘅賽事。
「頂級騎師」= 賽日前 365 日勝出數頭 6 名嘅騎師（逐賽日重算）。

| ID | 定義 |
|---|---|
| P1 換上頂級騎師 | 今仗頂級騎師，上仗唔係 |
| P2 換落非頂級（對照） | 上仗頂級騎師，今仗唔係 |
| P3 強騎練組合 | 該騎師×練馬師前 365 日 ≥ 15 次合作；組合入位率向騎師自己入位率收縮（k=20）後，高過騎師入位率 ≥ 8pp |
| P4 狀態差＋換上頂級騎師 | 近兩仗名次都 ≥ 6，而且 P1 |
| P5 快速回師 | 距上仗 ≤ 14 日 |
| P6 長休復出＋頂級騎師 | 距上仗 ≥ 60 日，而且今仗頂級騎師 |
| P7 馬重大變 | 排位體重同上仗差 ≥ 15 磅（絕對值） |

## 量度（凍結）

結果 = 入前三。效應 = 分層加權差（pattern − 非 pattern，權重 n₁n₀/(n₁+n₀)），bootstrap 以**賽日**做單位，2000 次。

- **L1 市場鏡頭**（D、V）：按最終獨贏賠率分層（≤3.0／3–6／6–12／12–25／>25）。問：pattern 有冇市場未反映嘅資訊。
- **L2 模型鏡頭**（M）：按現行模型排名分層（1–3／4–6／7+），排名來自 `hkjc_eval_harness run` 現行 code baseline。

## 判決（凍結）

1. **leakage**：所有特徵用到嘅紀錄日期 < 賽日；報告同日／之後行數要 = 0。
2. **L2 主判決**：10 個 pattern 一齊做 Holm（單邊，方向 = 發掘段 D 嘅方向）。
   Holm 後 p < 0.05 **而且** M 段 pattern 馬 ≥ 80 匹次 → 「overlay 候選」。
3. **L1 只作佐證**：V 段同方向而且 CI 唔跨零 = 「市場都未反映」，加分；但唔係必要條件（我哋模型唔睇賠率，
   市場反映咗嘅資訊模型都可能漏）。
4. 任何 pattern 冇過 L2 → 唔做 overlay，記錄數字。**唔准**事後改定義、門檻、分層或者窗口去救。
5. overlay 候選之後要：(a) 另開實驗用 walk-forward 揀幅度；(b) Stage 4 v3；(c) forward 確認。今次唔做。

### 機制拆解（事後診斷，唔係判決）

M 段，模型排名逐位分層（1…8、9+），騎師類別：up 換上頂級 914／stay 上仗今仗都頂級 1,718／down 換落 1,077／none 兩仗都唔係頂級 4,376：

| 對比 | 差 pp | 95% CI |
|---|---:|---|
| up vs none | +6.08 | [+1.85, +10.36] |
| stay vs none | +3.93 | [−1.10, +8.89] |
| up vs stay | +2.03 | [−2.43, +6.46] |
| down vs stay | −6.05 | [−10.39, −1.61] |
| down vs none | −1.80 | [−5.47, +2.00] |

主要效應似係「**今仗騎緊頂級騎師**」被模型低估，「換上」本身只係加少少（未顯著）；而引擎「換騎 −1.5」唔分方向，
換上頂級騎師都扣分。呢個拆解係睇完數據先做 → 只可以用嚟**設計**下一個實驗，唔算證據。
