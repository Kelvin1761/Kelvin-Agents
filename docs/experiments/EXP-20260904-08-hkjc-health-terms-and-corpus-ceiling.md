（今仗排位體重 1172 係後來公布嘅；早前個 racecard 嗰欄係空，所以之前讀到

## 二：三個項逐個量（16,959 個有上仗體重嘅 runner-start）

| 對比 | 差距 | 95% CI | 判斷 |
|---|---:|---|---|
| 長休 >75 日：回來**重咗**(>+5lb) − **輕咗**(<−5lb) | **+7.9pp** | [+2.1, +13.7] | **CI 不跨零 → 方向反** |
| 短休 ≤75 日：同一個對比 | −0.6pp | [−2.5, +1.2] | 跨零 → 冇訊號 |
| 長休 >75 日 − 正常間隔 21–75 日 | −3.7pp | [−6.4, −1.0] | CI 不跨零 → **長休罰分係啱嘅** |
| 急放 ≤20 日 − 正常間隔 21–75 日 | −1.3pp | [−2.7, +0.1] | 跨零 → 急放調整冇支持 |

逐桶（長休 >75 日，n=1,027）：

```
≤−15 lb  15.6%   ← 回來輕咗＝最差
−15..−5  20.6%
−5..+5   19.5%
+5..+15  27.2%
+15..+25 23.3%
>+25 lb  26.0%   ← 嘉應高昇落喺呢桶
```

**結論**：長休罰分要留；體重變幅罰分**喺短休冇訊號、喺長休方向反**。
嘉應高昇 +29 磅落喺實測第二好嗰桶，而引擎扣佢 5 分。

## 四：為咩今日冇一個候選判得到 —— 語料上限

193 場之下：

```
gold      baseline  6.74%   1 SE = 1.80pp
good      baseline 24.87%   1 SE = 3.11pp
champion  baseline 25.91%   1 SE = 3.15pp
1 場 = 0.52pp
```

**今日全部 arm 嘅差距係 1.0–1.6pp，即 0.41–0.72 個標準誤（2–3 場）。**
個閘唔係「否決」呢啲候選，佢係**睇唔到**佢哋。今日一共測過約 20 個候選
（負磅方向、官方評分入分、賽績線班次 floor、race_shape 內部、
馬匹健康三個項、走位匹配樣本門檻），全部落喺同一個噪音底。

**真正嘅瓶頸唔係設計，係語料量：**

```
有賽果嘅賽日        : 176
有評分 (Logic) 嘅賽日 : 27      ← 評估語料只用到 15%
可評估場次           : 193      （理論上約 1,700）
```

150 個賽日有賽果但從來冇入過引擎。如果補得返，`good` 嘅 1 SE 由 3.11pp
跌到約 **1.05pp**，今日全部 1.0–1.6pp 嘅差距就由 0.4 SE 變 1.0–1.5 SE ——
**由「量唔到」變「判得到」**。

⚠️ **但補唔到嘅原因要講清楚**：150 個賽日入面
- 1 個有 Facts（可以直接建 Logic）
- 4 個有排位表＋賽績（可以跑 Facts pipeline）
- **145 個完全冇源材料，只有賽果**

即係本地補得返只有 5 個賽日（約 +50 場，193 → 243，SE 3.11 → 2.79）。
其餘 145 個要**重新抽取賽前資料**（排位表＋賽績），係一個抽取工程，
唔係 code 修正。**呢個係「改善分析表現」嘅最高槓桿動作**，
因為佢會令今日每一個判唔到嘅候選變成判得到。

## 五：關於「用 ML 揀設計」

193 場之下用 ML 揀 fit/trip/PI 嘅設計 **等於擬合噪音**：1 場 = 0.52pp，
而 `good` 一個標準誤 = 6 場。任何靠 193 場排名表現揀出嚟嘅設計，
都係喺 0.4 SE 嘅差異上面做選擇。所以今次**冇**做 ML 設計搜索 ——
先補語料，再揀設計。呢個唔係拖延，係次序問題。
