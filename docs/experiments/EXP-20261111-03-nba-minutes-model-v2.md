# EXP-20261111-03：NBA 上場時間模型 v2 —— 細但真嘅改善；最大嘅獎喺當日正選名單

- **日期**：2026-11-11
- **平台**：NBA
- **起因**：EXP-20261111-02 顯示上場時間係 S 最大槓桿。Kelvin 要 S 佔更大份額，並提議睇 ESPN 有冇時間相關數據。
- **假設**：用賽前可知嘅資料（休息、讓分、正選角色、上一場缺陣）調整 S 嘅時間預測，可以減少時間誤差，從而改善 S 嘅腿機率。
- **冇改任何上線 code。** 候選係數凍結喺 `patches/nba_minutes_v2/min_coef2.json`，未接入引擎。

## ESPN 有乜（Kelvin 嘅問題）
- **有，而且上季全季已經 cache**：每場原始 summary 入面有 `starter`（正選）、`didNotPlay`＋原因、`pickcenter`（賽前讓分同總分盤）。
- **有，每日快照（11-01 起）**：depth chart、傷患名單。
- **冇**：逐場預計上場時間。Fantasy API 只有全季預測（每場平均時間、預計出賽場數），而且係當下快照，冇得回測。

## 語料同切法
- 球員-場次，全部特徵只用該場之前嘅比賽：2025-26 例行賽 1,235 場 ＋ 2026-27 至 11-09。母體：之前 ≥5 場、baseline 預測 ≥15 分鐘、有讓分。
- dev = 2025-26 至 2026-02-08（8,850）；holdout = 2025-26 之後（7,311）；**跨季樣外 = 2026-27（1,183）**。
- baseline = 現行 S 嘅做法（半衰期 3 場加權）。指標 = 時間 MAE，配對、按日 cluster bootstrap。
- dev 內 4 個時間 fold（訓練 = 之前全部）。

- 尾部（holdout）：模型話會打少嘅最低 10%，實際平均少 1.85 分鐘、22% 打少過 75%（其餘 14%）；話會打多嘅最高 10%，實際多 2.90 分鐘、31% 打多過 125%。
- 係數（dev）：休 >7 日 −2.5 分鐘；背靠背主力 −0.3、輪換 +1.1；讓分每分主力 −0.06（>8 分再 −0.08）、輪換 +0.07；上場正選 +0.85。
- 單獨加「高時間回落」「實力差代理」「波幅」「轉隊」都過唔到 fold（第一輪，`min_fit.py` 冇留）；用球隊淨勝分做大比數代理冇用，要真讓分先有效。

## 檢查
- **leakage-audit**：候選特徵全部係該場之前嘅比賽＋賽前讓分；腿測試用 21:00 自己抽嘅讓分。`pool_today`、`starts_today` 用咗當場資料，**明確標為上限，唔係候選**。母體限於有上場嘅球員（同注單結算一致：冇上場 = 作廢）。
- **ablation**：逐組加入見上表；總分盤冇貢獻，已剔出候選。
- 限制：baseline 係語料內重建（只用當季比賽），同 live S（季初撈上季）有少少出入；腿測試得 7 日；發佈機率係 MS（S 只佔 γ=0.11），所以對發佈機率嘅直接影響大約係 −0.0002，要重新擬合 MS 先知 S 可以佔幾多。

## 結論
時間模型 v2 候選係細但真嘅改善（時間 MAE −2%，S 腿 log-loss −0.0015，三個樣本都同方向）。更大嘅獎喺**當日正選名單**（−0.0044，三倍），呢個要喺臨近開波先知，21:00 只可以用 depth chart 代替（得 10 日快照，未測）。

**決定**：NEEDS MORE TESTING —— 候選未接線。下一步：(1) 將候選時間接入引擎做 shadow（S2，唔影響 `p_final`），預先登記「市場＋S2 重新擬合」對現行 MS 嘅 forward 測試；(2) 用 depth chart 快照測「預計正選」可以攞到幾多當日正選嘅上限。
