# EXP-20260904-02 — 冇今日排位體重時，唔可以聲稱「今仗較上仗」

- **日期**：2026-09-04；**平台**：HKJC
- **baseline**：`50caed7c`（= 當時 origin/main = production）
- **類別**：合約 §7 **正確性修正** —— 唔係表現改善，亦冇表現證據。

## 缺陷（可獨立證明）

`compute_weight_trend(entries, today_weight)`：

```python
if today_weight and today_weight > 0:
    weights = [today_weight] + weights
diffs = [weights[i] - weights[i+1] ...]
detail = f'今仗較上仗{diffs[0]:+d}lb'
```

HKJC 賽日當朝先公佈排位體重，所以**賽前兩日嘅 run 冇今日體重**：
`weights[0]` 其實係**上仗**，`diffs[0]` = 上仗 − 上上仗，
但段文字照樣寫「今仗較上仗」。實測 2026-09-06 ShaTin：**排位體重 0/120（0%）**。

呢個唔止係文字。`_candidate_health_risk_score`（live，`engine_core.py:742` 有 caller）
用關鍵詞 match 呢段文字去調 `risk_score`：

| 關鍵詞 | 調整 |
|---|---:|
| 急劇變化／急增／急減 | −5.0 |
| 顯著轉輕／大減 | −3.0 |
| 顯著轉重／大增 | −2.0 |
| 微增／微減 | +1.0 |

其中頭三個**只有喺今日體重已知時先成立**。有一個實際樣本寫住
`🔴急劇變化 (今仗較上仗+2lb)` —— 標籤同數字自相矛盾。

| `health_score` 變動 | +3.0 ×12、+4.0 ×10、+6.0 ×8（**全部向上**） |

⚠️ **更正**：本輪早前口頭講過「107 匹（91%）受影響」，**嗰個數係錯嘅** ——
佢包埋咗 `微增／微減`，而嗰兩個係多仗 range／平均推導，本來就唔需要今日體重。
真正錯分類嘅係 30 匹。

傳導率：`risk_score` 佔 `horse_health` 0.611，維度權重 0.0404 → **0.02468**。
所以最大影響 **+0.148 綜合戰力分**。今日 Race 1 第 2、3 名只差 **0.06**，
即係呢個幅度**足以翻轉平手**，唔可以當可忽略。

## 修法

`🔴急劇變化` 同 `🟠顯著轉重／轉輕` 兩個分支加 `today_known` 前置條件。
其餘分支（持續增磅／持續減磅／穩定／微增／微減）**完全不變** ——
佢哋描述歷史，本來就唔需要今日值。所有 return 加 `today_weight_known` 供下游判斷。

**賽日當朝體重出咗之後行為逐字不變** —— 已用測試釘死（同一段歷史，
有今日體重時仍然報 `🔴急劇變化 (今仗較上仗+20lb)`）。即係影響範圍只限賽前。

## 結論

呢個係修一個**可以獨立證明係錯**嘅聲稱：程式話「今仗較上仗」，而今仗個值唔存在。

但要明寫：**冇表現證據，唔係已證實嘅改善**，而且影響幅度足以翻轉平手場次。
