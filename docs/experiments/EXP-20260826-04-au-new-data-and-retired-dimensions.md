## Part A：`WinningTime` 速度評分

### 點解值得試

`WinningTime` 由 2026-08-09 起就寫入每條往績行（**52.1%** 有值），但
`inject_fact_anchors` 0 個引用、引擎 0 個引用。即係成個模型冇任何**絕對時間**
速度評分 —— 全世界最標準嗰個讓磅工具。唯一同時間有關嘅 `_STANDARD_600M`
係尾 600m 分段。

### 點樣砌（構造上唔可能中毒）

由**已 censor 嘅往績行**自己計，唔掂網站嗰啲會賽後刷新嘅總結欄位
（`J/H`、`WinRange`、`Ave $`、`1st/2nd/3rd Up` 全部係嗰類，見
`au_unused_field_power` 嘅註）：

```
個體時間 = WinningTime + margin × (2.4m / 平均速度)
速度評分 = −(個體時間 − track×distance 中位標準 − going 修正) / 公里數
```

848 個 track×distance 標準。going 修正自己驗證咗構造：
Good **−0.33**、Soft **+0.20**、Heavy **+1.53** 秒 —— 方向同幅度都符合物理。

## 附帶：`au_feature_ab` 個 `--min-depth` 預設會靜靜清空語料

`build_races` 讀 `source_compare.json` 攞 form depth，個檔唔存在就 `depth` 係空
dict，於是 `depth.get(name, 0) = 0 < --min-depth 4.0` → **每個場次都被隔走**，
輸出「0 場」再喺 `delta()` 度 `TypeError`。要 `--min-depth 0` 先跑到。
