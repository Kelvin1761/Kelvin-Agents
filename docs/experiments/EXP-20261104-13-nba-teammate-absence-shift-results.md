# EXP-20261104-13 結果：「缺陣變化」唔令模型更準，接手／復出腿都冇優勢

- **協議**：`EXP-20261104-13-nba-teammate-absence-shift-protocol.md`（commit `f6299691`，喺計結果前）
- **跑一次**：`docs/experiments/patches/nba_usage_shift/analyse.py`，輸出 `analyse_out.txt`
- **語料**：14,120 條有賽果嘅 over 腿（dev 7,611／holdout 6,509），機率 = live `nba_engine` 嘅 `p_final`。
- 缺陣變化 ≥ +0.10（今日少咗人）：2,171 條；≤ −0.10（有人復出）：3,130 條。

## H1：模型加「缺陣變化」項 —— REJECT
| | 基準 log-loss | Δ（候選 − 基準）[95% CI] |
|---|---|---|
| dev | 0.3478 | −0.00045 [−0.00110, +0.00056] |
| **holdout** | 0.4114 | **+0.00047 [+0.00003, +0.00166]**（顯著變差，雖然好細） |

- dev 擬合出嚟嘅方向唔一致：得分 +0.60、助攻 +0.76（少咗人 → 估高，方向啱），但籃板 −0.09、三分 −0.51（方向反）。
- **接手組**（今日少咗人）喺 holdout 嘅基準校準係 −3.3pp：live 模型本身已經**高估**咗呢班球員，唔係低估。**復出組**校準 −0.4pp，基本準確，冇「主力返嚟仲高估隊友」呢個漏洞。
- 判決：holdout 上限 > 0、δ 方向唔一致 → **REJECT**。

## 解讀
- 莊家同 live 模型都已經處理咗主力缺陣／復出：S 嘅分鐘權重（半衰期 3 場）同市場價本身就跟得好貼。
- 加多一個人手計嘅缺陣項，冇提供新資訊，只係加噪音。
- 同 EXP-20261104-12（臨場缺陣冇效應）結論一致：**「主力缺陣」呢條資訊，莊家已經計晒入價。**

## 檢查
- **leakage-audit**：PASS —— 今日缺陣只用開波前 package 嘅傷停名單；最近出場同份額全部截到美東比賽日之前（同 EXP-20261103-15 修訂 1 嘅重建）。
- 限制：季初球隊場數少（10-22 前後每隊得 1–3 場），「最近 5 場」好多時唔夠 5 場；Sportsbet 價係最後賽前刷新價（≈ 21:00 價，見 EXP-20261104-12）。

**決定**：H1 REJECT；H2 冇證據。冇改上線 code。
